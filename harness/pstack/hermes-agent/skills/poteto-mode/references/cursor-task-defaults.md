# Subagent defaults in Hermes

This reference is the Cursor-origin "task defaults" page, mapped to Hermes. Hermes `delegate_task` has no per-call model, effort, or speed field. Children inherit the session model. The one model pin lives in `~/.hermes/config.yaml`, and the slug-to-config mapping is in `../../docs/harness/claude-code.md` (relative to this skill's directory).

**Defaults for every `delegate_task` call.** Pass file pointers, not inlined context, and keep `tool_call` arguments small, because large inline briefs sever on this deployment (see `hermes-toolcall-size-pitfall.md`). Children run in the background by default and inherit the session model and reasoning effort. Put each role's instructions in `goal`/`context`; Hermes has no named agent type to select. A read-only role gets a brief that says "do not edit files" plus a `git status` check after it returns.

**Pin a model when a role needs a different one.** Set `delegation.model`, `delegation.provider`, and `delegation.reasoning_effort` in `~/.hermes/config.yaml` (drop any `-fast` suffix; it is a Cursor speed token with no Hermes equivalent). One pin covers every child at once, so the per-role model diversity the skills describe is advisory in Hermes. The `## pstack roles` lines in `~/.hermes/SOUL.md` record which family a role wants; to actually vary the model across a panel or race, re-pin `delegation.model` between seats. `auto` or `inherit-parent` means leave the pin unset so the child runs on the session model.

**Match effort to the job.** Start from the role's `/setup-pstack` budget, `xhigh` by default. Raise it up to `xhigh` for the hardest or subtlest work. Lower it one step for judgment and routine work. Verification stays on the `swarm workers` effort. Because `delegation.reasoning_effort` is also one pin, changing a single spawn's effort means re-pinning before that spawn or accepting the inherited effort and saying so.
